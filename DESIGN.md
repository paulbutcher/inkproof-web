# Inkproof.Web design

## Layout

Lasm's browser bindings (`Lasm.JS.Web`, `Lasm.UI`) ship with `@lasm/cli` and are not a Lake dependency, so modules that import them cannot build natively. Everything that does not need the browser (surface sizing, redraw state, log levels, attribute validation, the text cache) lives in modules that do not import Lasm, and is proved and tested natively with `lake`; they are the library `InkproofWeb` and the only modules in `API.lock`. The host is `Inkproof.Web.Host.*`, imported by the application that Lasm builds; `Inkproof.Web.Host.register` defines a chart element.

## Host

- One WebGL2 context, on a canvas that is never attached, serves every chart: a chart sizes it, runs the command list, and copies the result to its own 2D canvas, then draws its text over it. Only the encoded command list crosses to JavaScript, once per redraw. The interpreter's state lives as long as the context, so a list may draw buffers and programs an earlier list uploaded; handles are page-wide, so charts must not give one handle two meanings.
- A chart redraws only when invalidated: a new scene, a resize, a change of device pixel ratio or a restored context. Nothing is scheduled while it is idle.
- Resizes come from a `ResizeObserver` and ratio changes from the media query that names the current ratio, both bound from Lean. A lost context is kept restorable by cancelling the event and its interpreter state is discarded; `contextGeneration` increases and each chart dispatches `inkproof-contextrestored` (detail `generation`) before redrawing, so the consumer must answer with a list built as for a fresh context. When the last chart disconnects the host releases every buffer and program that remains and increases the generation, so a chart connected later starts fresh.
- Pointer input becomes Viewport `Input`s through Viewport's `Gesture` conversions and `Nav.input`: wheel zooms about the pointer, drag pans, shift-drag zooms to a box, two pointers pinch. `inkproof-pointer` reports the data position while over the plot; the element sets `touch-action: none`.
- `registerSized` gives its loader the canvas's CSS size, and calls it again 150ms after the size last changed, applying the result as `setScene` does, so the view, cursor and hidden series stay; `register` never reloads on resize. `registerPixels` also gives the backing store's size and reloads when the device pixel ratio changes, for commands in device pixels: a scissor or stroke width in them is in canvas pixels, which the host cannot rescale after the fact.
- Attributes are `src` (a URL of an encoded command list, or whatever the registered loader makes of it), `log-level`, `cursor`, `interaction`, `tooltip` and `legend`, each a list of words, one word for each choice, parsed into a Lean structure with a default for every field (`CursorStyle`, `Interaction`, `Tooltip.Style`, `Legend.Style`); a choice not named takes its default, and two words for one choice or an unknown word is an error. Invalid ones are logged and dispatched as `inkproof-error`; each redraw dispatches `inkproof-draw` with the backing size.
- The `group` attribute links elements: those with the same name share their x range, as Viewport's `Linked` does, and a view change on one gives the others the x range through Viewport's `Linked.followArray` and an `inkproof-view` event each, so the application answers each as it would its own. Each keeps its own y range; a chart taking `group` adopts the x range of those already in it, and removing the attribute unlinks it.
- The `cursor` attribute (`off`, `x`, `y` or `xy`) draws lines on the Canvas 2D layer at the data position under the pointer, and the pointer also puts the x position on the other charts of its group (a vertical line only, since y axes are not shared). Leaving the plot takes the cursor away. `Host.setCursor` sets or clears the x position from the page.
- The `select-x` word of `interaction` makes a drag edit a band over the chart's x range with Viewport's `Selection` (draw, move or resize, clamped to the starting view), instead of changing the chart's view, which stays at home; wheel and view keys are ignored. The band is drawn on the Canvas 2D layer and reported as `inkproof-select` (`null` bounds when cleared); `Host.setSelection` sets it. The other charts of its group take the band as their x range, and a chart that selects takes a group member's x range as its band, so a zoom or pan of a member moves it.
- The `markers` and `nearest-marker` words of `cursor` draws a dot on the Canvas 2D layer on each visible series at its point nearest the cursor's x, from `Access.traces` and the trace's colour, so moving the cursor redraws the overlay and never rebuilds the scene. A series with no value there, or one off the plot, gets none; `nearest` keeps the one nearest the pointer's y, or nearest in x when the pointer is over another chart of the group. A size word such as `6px` is the diameter in pixels and `filled` or `outline` the fill; a trace with `hollow` set is always filled, which is how a hollow series shows the point under the cursor.
- The `tooltip` attribute shows, in a `.tip` element of the shadow root (part `tooltip`), the series and position of the visible point nearest the cursor, measured along x or in plot pixels (`x`, `xy`), or with `shared` every visible series' value at the cursor's x; the points come from `Access.traces`; a trace's per-point `sizes` and `labels`, for bubbles, are named after the series and in the values, and the scene draws the bubbles (Scene's `compileScatterBy` and `compileRing`), with its right-axis series given to the trace in the left axis's coordinates. The attribute is a list of words (`Tooltip.parse`), like `legend`. The box is placed (`Tooltip.Style.place`) against the nearest point or the pointer, opening from one of four corners at an offset (8 pixels, top right, as before); where it would leave the element it opens the other way, and where neither fits it is moved inside. Its look comes from `--inkproof-tooltip-*` custom properties, which fall back to the former fixed style. The `legend` attribute fills a `.legend` element with one button per series: its colour, its name and its value at the cursor's x (the point nearest in x), a dash with no cursor. The attribute is a list of words (`Legend.parseStyle`): a placement over the plot at a corner, or `below-left`, `below-center` or `below-right` (`bottom`) in a row of the element's own flex column, so the canvas, and the CSS size a loader is given, are the element less that row (pointer positions are taken from the canvas); a `vertical` or `horizontal` layout, a column over the plot and a wrapping row below it unless given; `static`, which leaves out the values; and `x`, `y`, `no-x`, `no-y` for the cursor readout, shown with values and hidden without. The stylesheet places the legend by `data-place` and `data-layout` on it and `data-legend-below` on the element, which the host sets. A click toggles the series, the chart keeps which are hidden across scenes of the same series count, and `inkproof-series` (detail `series`, `hidden`) is dispatched; the canvas is not redrawn, so the application answers by setting a scene without that series.
- The `highlight` attribute (`on` or `off`, `Highlight.parse`) fills the topmost `Access.items` rectangle under the pointer with a `.highlight` overlay in the shadow root (part `highlight`), so the scene is not redrawn per move; the application gives the rectangles in data coordinates, since it knows what it drew, and `Item.hit` picks the last one containing the point. The overlay is cut to the plot (`Item.screenRect`) and takes its colour from `--inkproof-highlight-background`, `-opacity`, `-border-width` and `-border-color`, falling back to the theme's legend colour. An item's description replaces the nearest point's tooltip, opening from the pointer (against the `tooltip` attribute's style if there is one); an item with none leaves it.
- The `chart-title` attribute fills a `.title` element (part `title`) above the canvas, and sets `data-title` on the element, which makes it a flex column so the canvas, and the CSS size a loader is given, are the element less the title's row. It is not `title`, which the browser shows as a tooltip. The tooltip's position adds the canvas's offset in the element. Minor gridlines are not the element's: Scene's `MinorGrid` puts them in the scene's commands, from Axis's minor ticks.
- The `theme` attribute (`ChartTheme.parse`: `light`, `dark` or `auto`, which follows `prefers-color-scheme` when the attribute is set or changed) resolves to a Scene `Theme`. The host fills the canvas with its background under the data layers, sets `data-theme` on the element so the stylesheet takes the tooltip, legend and title colours from the theme (`--inkproof-*` properties still win), and gives the theme to a loader registered with `registerThemed`, which builds the axes, gridlines and labels in the scene with `Theme.applyAxis`, since the scene, not the host, owns them. Without the attribute nothing changes. A change to it loads the scene again.
- The `number-format` attribute is a list of words (`Numbers.parse`) giving Axis's `NumberFormat`, which the legend, its cursor readout and the tooltip write numbers with (`showNumber`, which falls back to `showFloat` for a value the format cannot write); with no attribute, numbers are written by `showFloat`. The legend's look comes from `--inkproof-legend-*` custom properties, as the tooltip's does from `--inkproof-tooltip-*`. An axis label's font and colour come from the `TextStyle` of the `PlacedLabel` Scene gives (`Label.ofPlaced`), so the application sets them in the scene.
- Fetching runs as `Async` on the main thread, which never blocks; Lean in Lasm's browser target is single-threaded, so there is no worker. Tile queries (`queryTiles`, and `queryColumns` for one aggregate per pixel column) fetch each tile with `fetchTile`, which takes an optional byte range, and only the tiles a range touches, one at a time, merge them with Core's aggregation (`Aggregate.foldTilesM`, which is `foldTiles` with the fetch in a monad), and yield to the event loop after each tile, so a long query never holds the main thread. A failed tile is logged with its URL and fails the query. A `TileCache M` passed to a query keeps the decoded tiles and byte ranges, at most a stated number, least recently used evicted, so queries sharing it fetch and decode each once; queries running at once that need the same tile share one fetch, and a failed one is logged once, fails each waiter and is never stored. `queryColumnsFrom` serves a pyramid stored from level `k0`: columns at least `branching ^ k0` leaves wide come from the stored levels, narrower ones from leaves the application's source maps to raw byte ranges, a leaf in no range being a gap. A worker is not used: it would need a second Lasm build and a second shim. Text measurement is `Canvas 2D measureText`, cached by font and text. A text that could not be measured is NaN, which Axis drops rather than places.

## Accessibility

- A scene carries an `Access`: the chart's name, series, point count, optional summary, a data table and the view configuration. The element becomes focusable (`tabindex` 0 unless set), takes the name as `aria-label` and the summary as `aria-description`, and holds the data in a visually hidden table; the `show-table` attribute swaps the canvas for it.
- Keys map to a `Command` (pure, native), and `Nav.apply` applies it: zoom and pan go through Viewport's `View.step`, so keys and pointer share one path. The host reports changes as `inkproof-view` and `inkproof-cursor` events and announces them in a polite live region; the application answers a view change with `Host.setScene`, which replaces the scene but keeps the `Nav` (its cursor clamped to the new data) and the GPU state, and a page's own controls issue a `Command` with `Host.apply`. Keys with modifiers, and keys the chart does not use, are left to the browser.

## Lean core declarations

- `Nearest.argmin` is `List.minOn?`, and `argmin_mem` and `argmin_eq_none` follow from it. `argmin_least` keeps its own induction: core's order lemmas need `IsLinearPreorder Float`, which NaN rules out, so they hold only under the `IsOrdered` hypothesis, which core cannot state. `minOn?` is a plain fold, so it adds nothing to the Lasm build.
- `nearestBy` is not `minOn?` over the filtered list: it replaces the best on a strict `<`, `minOn` on `¬ best ≤ new`, and the two differ when a distance is NaN (a NaN or infinite `x`).

## Building an application

An application's `package.json` depends on `gpu-js` (the module `inkproof-gpu-js`, a copy of the interpreter the pinned Gpu release generates, written by `scripts/gpu-module.sh <dir>` and checked by the tests) and on `shim/inkproof-web-element` (the shim below), both by `file:` path. Lasm resolves them through Vite and `@lasm/cli/vite`; a static `lasm build` cannot resolve npm modules. `test/` is a working example.
